What Phase 3 built

  1. A bridge between ns-3 and Python. The simulator pauses at every decision, sends what the UAV knows over a pipe, and waits for the next cluster. A new external routing policy in C++.
  2. The learning problem. 13 features per cluster, all from the UAV's own records: last reported buffer and energy, promise slack, missed meetings, lateness estimate. No future information, checked by a test.
  3. The reward. Data delivered, minus UAV energy, broken promises, cluster-head listening energy, and (for ER-PPO) the risk of arriving late.
  4. The agent. MaskablePPO with a per-cluster scoring network and self-attention, warm-started by copying the tour, then trained for 300 000 decisions (about 20 minutes per variant).
  5. The ablation. A1 plain PPO, A2 adds the lateness estimate, A3 adds adaptive wake windows, A4 adds the risk term (full ER-PPO).

Why PPO matches the tour instead of beating it

Tested on 5 held-out hotspot networks with small buffers, where the tour loses 8.9 % of data to overflow. If any policy could beat the tour, it would be here.

PPO chose the tour's next stop at 100 % of decisions. Hand-written detours fly 279 m per visit against the tour's 129 m, and every skipped cluster misses the window it was promised. Under promise-based wake-up, changing the visiting order costs more than it gains, so the tour is close to optimal here.

Talk script

About four minutes. Start the replay before you begin.

0:00

Phase 3 is the reinforcement learning part. The question is: at every stop, which cluster should the UAV fly to next? I connected ns-3 to Python so that the simulator pauses at each decision and a PPO agent picks the next cluster.

0:40

The agent only sees what the UAV itself knows: the last buffer and energy each cluster head reported, how much slack is left on each promise, past missed meetings and its own lateness record. Nothing from the future. There is a test that checks this.

1:10

Point at the replay. This is one two-hour mission on a network the agent never saw. Left is the ETA-aware tour, middle is ER-PPO, right is the data-greedy baseline from Phase 2. PPO and the tour both reach about 97 % delivery with about 90 % of meetings on time. Data-greedy chases full buffers across the map, keeps only 16 % of its promised meetings, and cluster heads burn more than twice the energy listening for it.

2:00

Getting here took several fixes. With the first reward every agent learned to hover and rely on the cluster heads' retry listening, so I added cluster-head energy to the reward. Then three training fixes: a discount based on mission time instead of per decision, imitation of the tour that fades out, and an early penalty on promises that can no longer be kept. On-time meetings went from 83 to 90 %.

2:50

On ten held-out networks, all four ablation variants match the tour. The differences have confidence intervals that include zero. The adaptive wake window gives the clearest gain, and the risk term adds a little more.

3:20

So why doesn't PPO beat the tour? I tested that directly. Even on uneven traffic where the tour loses 9 % of data to overflow, PPO converges to exactly the tour, and hand-written detour rules lose badly, because every detour breaks promises to the clusters it skips. With promise-based wake-up the tour is close to optimal, and PPO learning to match it is the correct result. All of this is reproducible with one command for Phase 4.

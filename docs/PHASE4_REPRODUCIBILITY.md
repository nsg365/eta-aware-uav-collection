# Phase 4 clean-clone reproducibility

This guide reproduces the Phase 4 simulation results and generated analyses from a clean checkout. It includes the six original Phase 4 experiment groups and the matched A7/A8/A9/wake-mode ablations.

## 1. Prerequisites

Use the environment documented in [`SETUP.md`](SETUP.md): Linux or WSL2 Ubuntu 24.04, Python 3.11+ (3.12 recommended), a supported C++ compiler, CMake, and **ns-3.47**. Keep the project and ns-3 source in sibling directories so the default `NS3_DIR` works:

```text
~/mlown/
├── ns3-workspace/ns-3.47/
└── wsn-uav/
```

Install the system tools and Python packages using the commands in `SETUP.md`. In particular:

```bash
sudo apt update
sudo apt install -y build-essential cmake ninja-build git wget bzip2 \
                    python3 python3-venv python3-pip

mkdir -p ~/mlown/ns3-workspace
cd ~/mlown/ns3-workspace
wget https://www.nsnam.org/releases/ns-3.47.tar.bz2
# Verify the checksum shown in docs/SETUP.md before extracting.
tar xjf ns-3.47.tar.bz2
cd ns-3.47
./ns3 configure --enable-modules="wifi;energy;internet;mobility"
```

## 2. Clone the repository

After the Phase 4 PR is merged, clone the default branch:

```bash
cd ~/mlown
git clone https://github.com/nsg365/eta-aware-uav-collection.git wsn-uav
cd wsn-uav
```

Before the PR is merged, use the feature branch instead:

```bash
git clone --branch phase4-thiaana https://github.com/nsg365/eta-aware-uav-collection.git wsn-uav
cd wsn-uav
```

Create and activate the virtual environment:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

The requirements include the Phase 3 policy-evaluation stack (including PyTorch), so this is a relatively large install. Do not omit it if reproducing the full original Phase 4 analysis and PPO evaluation. Matplotlib is installed as a dependency of the pinned Stable-Baselines3 stack and is also checked by the reproduction launcher.

## 3. Preflight

Run the read-only checks:

```bash
python scripts/reproduce_phase4.py --preflight-only
```

The preflight checks the committed Phase 3 evaluation `runs.csv`, the eight PPO training-monitor CSVs, all ten Phase 4 TOML configurations, the experiment/analysis scripts, and the Python imports. These baseline inputs and monitor logs are version-controlled; they are not expected to be generated by the Phase 4 run.

## 4. Run the complete experiment and analysis pipeline

With ns-3.47 located at `../ns3-workspace/ns-3.47`, run:

```bash
python scripts/reproduce_phase4.py -j 4
```

This single command:

1. Links this repository into the ns-3.47 scratch tree and builds `wsn-uav` and `wsn-uav-range`.
2. Runs the test suite.
3. Runs the six original Phase 4 groups via `analysis/run_phase4.py`: ETA uncertainty quantiles, network sizes, wake-window widths, UAV delay probability, CH failure rate, and clock drift. It regenerates their aggregation tables and existing Phase 4 statistics/figures.
4. Runs the four matched ablation configurations: A7 backup CH, A8 immediate missed-meeting failover, A9 survey lap, and the three-way wake-mode comparison. A7/A8 use four workers, A9 uses two, and wake modes use four.
5. Validates that the four ablation CSVs contain 60, 60, 60 and 90 rows respectively, with the expected variants and no duplicate `(network size, seed, variant)` cells.
6. Regenerates paired ablation statistics, descriptive summaries, the Markdown report, and figures.

The original Phase 4 orchestrator is intentionally called with `--overwrite`: the repository contains a tracked seed/baseline result at `results_phase4/eta_multiseed/runs.csv`. This option reruns the configured experiment groups; it does not delete unrelated files.

If ns-3 is already built in the expected location, use:

```bash
python scripts/reproduce_phase4.py --skip-build -j 4
```

For a different ns-3 location, set `NS3_DIR`:

```bash
export NS3_DIR=/absolute/path/to/ns-3.47
python scripts/reproduce_phase4.py -j 4
```

## 5. Analysis-only regeneration

If all simulation `runs.csv` files already exist, regenerate analyses without rerunning simulations:

```bash
python scripts/reproduce_phase4.py --analysis-only
```

This mode expects the six original Phase 4 run CSVs and all four matched-ablation run CSVs to be present. It deliberately fails rather than silently omitting a missing experiment.

## 6. Expected output locations

Original Phase 4 summaries and figures are written under `results_phase4/`, including each experiment's `summary.csv`/`summary.md`, paired-analysis CSVs, and figure directories.

The matched ablation outputs are written under `results_phase4_full_ablation/`:

- `a7_matched_multiseed/runs.csv`
- `a8_matched_multiseed/runs.csv`
- `a9_matched_multiseed/runs.csv`
- `phase4_wake_modes_multiseed/runs.csv`
- `analysis/paired_statistics.csv`
- `analysis/variant_summary_by_size.csv`
- `analysis/ablation_report.md`
- `analysis/figures/*.png`

The runner also writes per-run directories (topology, configuration, metrics and logs) beneath the corresponding result roots. These are generated artifacts and need not be committed when the aggregate `runs.csv` and analysis outputs are versioned.

## 7. Dry run and validation

To inspect the command sequence without building or launching simulations:

```bash
python scripts/reproduce_phase4.py --dry-run
```

To run tests and config validation separately:

```bash
python -m pytest -q
python scripts/validate_phase4_configs.py
python -m py_compile scripts/reproduce_phase4.py scripts/analyze_matched_ablations.py
```

## Reproducibility notes

- Matched variants use the same `(network size, seed)` topology and ns-3 run number, providing common random numbers for paired comparisons.
- The paired ablation analysis expects 10 matched seeds per network size.
- The original Phase 4 lifetime analysis preserves censoring information; censored lifetimes must not be treated as observed death times.
- UAV flight/hover energy fields ending in `_est` are analytic estimates. They must be labelled as estimates, not as ns-3 simulated radio energy.
- Metric and parameter-sweep figures are regenerated from the experiment `runs.csv` outputs. PPO training curves are regenerated from the version-controlled per-episode Monitor CSV logs; those episode-level samples are not contained in the simulation `runs.csv` schema, so they cannot honestly be reconstructed from `runs.csv` alone.
- Results can vary across toolchain/platform versions. Record the OS, compiler, CMake, Python and ns-3 versions alongside any regenerated submission results.
